# 完美存档原生验证工具

当前验证方式为卡口验证：求解前置参数 → 设置隔离状态 → 执行原生任务 → 核对分支及状态变化。按用户2026-10-07最终授权，连续卡口及线路终点验证不再作为本次提交条件，当前项目变更按已有证据交付。历史报告保留；后续继续验证时，未知、未执行和仅有静态清单的项不能计为通过。

顺序验收应在同一隔离状态内按原生任务／依赖关系选择下一卡口，保留累计副作用，仅重新求解当前卡口；后面的前置条件可以替换已经完成卡口的冲突条件。最后可执行卡口须有原生完成证据，然后将累计原生后置事实与实际读取的Mod生成档比较，逐字段定位差异。不是按源码行号排序，也不把“没有候选”当作走通。`gate_sequence.py`已实现这套调度与对照核心；目前其顺序行为只有工具测试，尚未完成全支线原生选择／执行适配，不能称顺序验收已通过。下文探针仍属局部独立卡口证据。

当前验收方式为参数驱动卡口测试，按用户最新要求停止导航遍历。下文导航脚本保留作历史诊断工具，不再自动运行。卡口探针从实际注册观察器绑定ctx，求解完整前置链后，在当前引擎新建的一次性状态中应用参数并经原生event.emit／event.next派发；比较实际分支与状态变化，完成后恢复现场、导入的持久化对象别名和随机状态。时段分别验证，quick-6保持不变。每批选择1至64个候选，每个候选最多展开16个独立原生菜单／脚本标量参数方案；未执行、未知输入、派发异常及预算截止均不计通过。

只在仓库`.codex_tmp`内的官方游戏隔离副本运行；原版游戏目录不接受探针。副本须已安装当前Mod并生成`quick-6`。`run_gate_inventory.ps1`接受任意隔离副本路径及已有测试入口名，不限制Mod版本；每个进程有截止保护，结束或失败均恢复原测试入口，备份留在副本根目录。

```powershell
tools/native_tests/run_gate_inventory.ps1 -StagePaths @('.codex_tmp/perfect-standalone8194') -ProbeNames @('zzz_perfect_inspect.rpy') -ParameterOffset 0 -ParameterLimit 8
```

输出`perfect_gate_inventory.json`、分段JSON及Markdown清单；`parameter_gate_checkpoints.jsonl`逐项保存开始／结束、未解条件和任务队列状态。`-GateIds`可按清单中的实际注册ID定向选择，ID仅用于测试，不进入生产Mod。启动前检查探针Python语法、已安装Mod源文件集合和摘要、孤立编译文件；原生脚本错误立即终止并恢复入口，可用`-HostPython`指定预检查解释器。报告固定本次工具、已安装Mod及quick-6指纹；工具变更后不能把旧分段当作新代码验收。旧分段在同名重跑前独立归档。

指定`-GateIds`时仍保留完整语法清单，但只对所选卡口进行前置求解和原生读取验证。其他项显式记为`not_requested_in_this_batch`，不计为通过或不可达。数值乘、除、整除及取模仅接受原生数值操作数；除零和非有限结果保持未知，不调用实体的重载运算。每批需要为报告保存留出时间；预算截止保留轨迹，缩小批次后独立重试。

可同时指定`-BranchOffsets`按所选卡口的源偏移选择实际分支，避免求解器扩展后候选序号变化导致复核错项。基线见证只用于候选选择；每次执行必须在当前隔离状态初始化和日程安排之后重新求解。纯局部Random构造器的已有整数输入允许明确的0至63有限测试域，保持全局随机状态不变；无见证不能称不可达。

`-LoadedSnapshotOnly`在新进程实际读取隔离副本quick-6后，输出`loaded_generated_state.json`，包含原生存储快照、日期／房间、Mod及存档摘要。该模式不重新生成存档、不执行卡口，不覆盖已有分段；不能与SourceOnly同时使用。它只是对照的生成档一侧，仍须独立的连续原生执行参照。历史局部后置记录可作辅助对照，但不能补齐新顺序卡口验收；日期戳等差异必须保留原始值并核对原生读条件，不能直接写回Mod或静默忽略。

游戏Partial、关键词默认值、闭包和注册事件参数必须按原生绑定协议读取。ctx标记可能是整数位置参数计数，按原生真值判断绑定，不能仅与True做身份比较。注册的None是实际字面量；未提供事件字段可显式选择原生声明默认值作为测试输入，必须记录来源，不能称为观测到的玩家事件。时钟缺省输入可选择原生枚举并记录来源；注册枚举常量保持固定值，只有明确来自当前时钟的输入随独立时段变化。没有默认值且未绑定的必需参数保持未知。读取协议允许已核对的资格判断、时钟枚举、归属／相遇记忆、事件注册集合的身份成员判断和带明确种子的局部Random.random；任意调用、全局随机数和写操作屏障不自动放行。条件路径数量含不同前置链，统计唯一条件时应按源函数、代码块、字节码偏移去重。

原生Task按其真实返回哨兵和_choice初始化，防止复用旧返回值跳过脚本。剧情脚本通过原生新上下文执行Python、If、Call、Menu和Return，TranslateSay保留翻译分派及已读记录；对白、场景显示和暂停仅省略呈现，不算界面验收。多选菜单只使用实际条件启用的payload，每个方案从新状态开始；未适配的call screen不伪造结果。遇到阻塞时，从原生If条件的现有存储标量字段、比较字面量和阈值推导额外测试参数，在生产构造和时间安排完成后设置，再独立重试。例如原生简单模式分支实际调用游戏自带mini.skip并返回，不伪造小游戏返回值；这不验收被该分支绕开的小游戏操作。时钟字段不混入此参数域。脚本返回后继续按原生顺序执行其队列，不能只核对菜单返回。初始派发仅选择目标处理器，其他初始处理器的完整排序仍未验收。

状态快照读取目录对象的存储字段，以及嵌套原生辅助对象的字典和存储槽；保留枚举、绑定回调和非字符串键字典的类型，避免漏掉孕期或子女计数变化。集合按内容稳定排序，目录引用和循环单独表示；不执行计算属性或回调。展示字段及根对象when不在存储快照范围，未知类型和递归预算明确记录，不能据此宣称完整世界状态等价。

目前事件、共享函数、脚本条件和资源规则清单不等于所有界面及动态流程的完备枚举。`all_gates_passed`保持false；实际响应验收仍需包括完成后退役的依据、状态转移前后、局部对话变量、设备、互斥菜单及场景交互。原生时钟场景分别测试；不能把相互排斥的时段合并到生成档。最终生成档仍为第1天主角房间。

可用当前引擎的原生解析器直接扫描官方反编译的.rpy及.rpym；不执行源码。独立清单包括未激活标签、If／Menu／While、Python条件及带前置的语句、字段读写依赖、静态／动态调用和SL2界面条件；每份源文件记录摘要。解析失败、动态目标、循环、模块命名空间、call screen和未知语句协议仍需原生验证，源码清单不等于全部卡口已通过。游戏Python模块中的注册／日程判断继续使用原生清单，不因扫描rpy而忽略。

`segment_complete`只表示本进程结束，须按同一范围继续；`navigation_scan_complete`只表示当前可见控件前沿已耗尽，不表示全部卡口通过。`-IncludeInteractions`增加设备、物品及实际菜单分支；不同范围不能混用检查点。使用原生时钟／睡眠按钮准备较晚时段，quick-6不变；动作引起的跨时段后续单独列为待测，不混入同一时段。密码锁读取本版小游戏声明的目标，逐个执行真实输入按钮；未知玩法或敏感控件继续登记未验收。

设备可能不完整保存临时界面状态。扩展交互测试复用最近的原生导航存档点（包括地图），只重放进入设备或菜单所需的剩余输入；没有导航存档点的定向用例才从房间基线重放。存档点前缀必须与完整输入来源一致，设备快照不能充当导航存档点；恢复后的源界面仍严格核对。菜单只选择实际渲染且可用的控件；一次交互返回普通导航时结束本用例，不再带着该事务的副作用重复探索全地图。该隔离策略不证明未知状态间等价，其他组合仍不继承通过。

每个动作的15秒截止在设备等待分支前检查，单个用例累计重放另有30秒截止，不因每步动作重置。超时保留失败路径，不跳过或算作通过。银行设备通过原生输入、存入、取出及退出按钮验证双账本和调用方回写；未知设备协议仍需另行验证。

原生脚本的字面量`call screen`按实际显示的界面记录响应，避免将正常设备输入等待误判为游戏死循环；表达式屏幕名不执行求值。只有已支持的真实Emit／Return输入进入下一步，其他敏感控件仍登记待适配。进入设备界面不证明设备操作全部通过。

`-SeedCasePath`接收隔离目录中保存的单个原生失败动作（包括原始source_path与source_context），从未改变的quick-6重放。它只支持新的定向交互扫描，不接受Resume；来源不匹配仍失败。输出`targeted_interaction_tick_<tick>.json`，报告保留seed_case；其前沿耗尽只对应定向用例，不能代替全量扫描。工具源码变更后保留原全量报告，不将旧前沿伪装成新探针验证结果。

续测核对quick-6、探针源码摘要、版本、时段及范围；探针改变后重新建立前沿。失败保留首个报告，修复后通过`-RecoveryNote`说明诊断再重试同一动作；不能跳过失败动作。重新开始时自动归档旧报告，未知控件、状态差异与缺少输入适配器保持未通过。

`native_branch_trace.py`只观察真实输入期间实际执行的原生逻辑条件跳转，不重新求值条件、不改操作数。按模块、源位置、常量及嵌套代码指纹区分分支，保存首个参数样本；预算截断、未到达分支和后置状态仍未验证。已有调试器运行时拒绝替换其trace。实际渲染控件相同但游戏状态不同的分支保留在`unexplored_world_variants`，不会自动继承通过。

`branch_coverage.py`将原生响应报告与卡口清单按代码来源和偏移对照；版本和quick-6指纹必须一致。旧报告缺少指纹时拒绝合并。两个分支方向的执行记录也只证明执行，不证明前置完整、所有任务完成或原生后置状态正确。报告继续保持`all_gates_passed=false`。

```powershell
python tools/native_tests/branch_coverage.py .codex_tmp/perfect-standalone8194/perfect_gate_inventory.json .codex_tmp/perfect-standalone8194/interactions_tick_4.json --output .codex_tmp/perfect-standalone8194/native_branch_coverage.json
```
