## 发版检查清单

1. 确认目标游戏版本，并核对反编译源与 `translation_context` 中记录的行号、ID 是否仍匹配。
2. 运行完整审计（与 CI 相同的命令，见 [index.md](index.md)），要求全部退出码为 0。
3. 确认没有残留的 STALE 记录：`python tools/audit_manual_coverage.py` 应报告 0 个过期文件、0 个缺失文件。
4. 更新 `CHANGELOG.md`，写清本版面向的游戏版本、翻译改动和已知限制。
5. 在隔离的匹配版本游戏副本中构建并校验 RPA（`tools/build_rpa.py --require-compiled`），不要直接对用户的游戏目录操作。
6. 发布后在 Release 说明中写明：对应游戏版本、安装路径（`game/zh_hans.rpa`）、已知问题，以及不要与散装 `tl/zh_hans` 同时安装。

## 构建产物现状

- `dist/zh_hans.rpa` 与 `dist/chinese.rpa` 是历史构建产物，可能落后于当前翻译源。构建时间见文件修改时间，最新翻译改动时间见 `git log -1`。
- 判断产物是否过期：比较 `dist/zh_hans.rpa` 修改时间与 `tl/zh_hans` 中最新的改动时间；不一致时以翻译源为准。
- 默认不把构建产物提交进改动；正式发布由 `.github/workflows/build-chinese-rpa.yml` 在 Release 触发时生成。
- `.codex_tmp/` 是本地临时目录，不进入版本管理，也不参与发布。

## 上游游戏更新时的处理

1. 用 `tools/audit_source_comments.py --source-root <新版反编译目录>` 核对源注释与对白摘要，先定位行号漂移的翻译块。
2. 以引擎实际翻译节点的 filename 与 linenumber 为准调整块位置，不按反编译文本的物理行号猜测。
3. 检查引擎报告的 orphan 清单，确认哪些旧块已不再使用；删除前同时检查 `sentence_patterns.json` 是否仍有对应原文。
4. 新增对白按 [style_guide.md](style_guide.md) 的提取文本维护规则归档，并同步 `manual_review.json` 的哈希与行号。
5. 在 `CHANGELOG.md` 与上表登记新的游戏版本与汉化版本对应关系。
