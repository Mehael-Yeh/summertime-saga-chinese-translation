# 中文精修风格指南

更新时间：2026-09-12

## 每文件工作流

1. 完整读取文件；不足时读取前后文件。
2. 先判断地点、剧情阶段、说话人、关系、目的、情绪和分支。
3. 逐条对照英文，识别连续拆句、代词、双关、讽刺、调情及成人含义。
4. 同一英文名词、组合词、称呼或固定表达在短距离内出现 2 次及以上时，先执行跨文件复查并登记，不在当前几行内孤立定译。
5. 只修改目标中文字符串，不移动、合并或拆分 Ren’Py 语句。
6. 完成英文对照、纯中文复读、程序格式三轮检查。
7. 运行 `python tools/validate_translations.py --changed` 和 `python -X utf8 tools/audit_recurring_terms.py --changed --fail-on-mismatch`，再检查 `git diff`。

## 中英文间距（强制）

- 玩家可见译文中，英文姓名、品牌、缩写与相邻中文或中文标点之间不加空格，例如“我找Anon聊过了”“欢迎光临Tony披萨店”“看Pink Channel节目”。
- 英文词组内部的空格保持原样，例如 `Pink Channel`、`Blue Falcon`；不合并英文单词，不改姓名拼写。变量渲染的人名同样直接接中文，例如“我和[saga.cast.debbie]一起”。
- `{i}` 等显示标签不构成可见间隔，标签两侧按实际可见文字处理；变量内部、标签参数、代码、资源路径、英文原文及显式排版间隔不修改。
- 运行 `python -X utf8 tools/audit_mixed_spacing.py` 检查全仓译文，要求零不一致。

## 非地名英文残留

- 月份全称 January 至 December 保留英文：用户确认 June 与角色名共用字符串，翻译成“六月”会影响角色姓名显示。不得用文件位置或静态校验例外假定运行时翻译隔离；未经验证的全局 June→六月 映射禁止加入。原有月份缩写译法本轮不变。

- 按语言而非字母判断：本轮只汉化英文，意大利语、日语、法语等及其罗马字不动；混合语言句不批量替换。
- 普通词句、操作说明与已有中文术语的物品名应翻译；人物姓名、字谜、品牌型号、按键和程序标识先核对用途。具体已修复项、保留理由和待查项见 `english_residuals.md`。
- 不把开发占位符猜译为剧情；当源注释与目标标识符不一致时单列待查。

## 中文表达

- 优先准确、连贯和角色化，不逐词硬译。
- 删除不必要的英文式主语、被动句、从句套叠和“我想知道是否”等机翻结构。
- 不为追求流畅而改变剧情事实、人物关系、行为主体、情绪强度或成人含义。
- 不擅自加梗、加心理活动、加色情细节，也不净化原文。
- 同一角色在同一关系阶段保持稳定语气，但不要把所有角色翻成同一种网络口吻。
- 角色使用引号复述前文台词时，引号内译文必须与前文实际译文完全一致；不得在复述时另换同义词，导致剧情回扣失效。

## 重复称呼、口癖与专名

- 同一表达短距离出现 2 次及以上，是强制复查触发条件；优先判断人物专属称呼、口癖、车辆/物品/地点专名和关系阶段用语。
- 先用 `python -X utf8 tools/audit_recurring_terms.py --query "英文短语"` 搜索全仓英文原文与现有中文，再确定译法。
- 已确认条目写入 `translation_context/recurring_terms.md` 和机器可读的 `translation_context/recurring_terms.json`；人物相关条目同时更新角色档案，固定译法同步更新术语表。
- 跨文件命中不等于可以立即全局替换。未通读的文件只加入复查队列，进入该文件并理解完整场景后再修改。
- 每个已处理文件都要运行重复术语审计；审计脚本只报告，不自动重写。

## 地点名称核对

- 地点定译先核对设定、语气和双关，兼顾信达雅；不合适的 UI 旧译须连同引用同步纠正。地点专名出现一次即核对 `base_box/sets.rpy` 与 `res/meta/sets.rpy` 的 UI 译名，跨对话、任务、物品说明、选项保持一致；固定表及例外见 `terminology.md` 的“地名与 UI 一致性”。
- 不把“人物姓名保留英文”扩展到店名。允许增加类别词，不允许替换核心译名；普通场所词和自然简称按上下文处理。
- 地名专项排查以英中对应和前后文为依据，只修地名相关文本；完成后运行全仓术语审计以及翻译结构检查。

## 连续拆句

- 日记等抽取字符串不一定按显示顺序存放；先核对实际拼接关系，再判断指代与语序。不得把相邻条目误当作连续句，也不得为了中文顺序移动翻译块或格式标签。
- 区分“全仓静态扫描”和“逐句语义审校”；检查记录须注明覆盖数量、已修订范围、待核实项及是否经过游戏内验证。

- 遇到 `...`、`extend`、未完成谓语/宾语或被打断句，必须把连续多行作为一个语义单元理解。英文纯省略号通常译为中文省略号 `……`，不得因编码或管道问题写成 `??`。
- 代码行数和顺序保持不变；只在各字符串内部安排中文停顿和衔接。

## 成人场景

- 与普通剧情同等优先；完整翻译呻吟、喘息、身体反应、性行为和粗俗用语。
- 原文含蓄/挑逗/露骨/粗俗的层级必须对应，不自动升级或降级。
- 主动、被动、命令、抗拒、羞耻、试探和欲望不能混淆。
- 女性角色明确要求与对方发生性行为，且中文动作义采用“操某人／操屄”一类直白结构时，优先把动作字写作“肏”；感叹、惊讶、愤怒或辱骂中的“操”仍保留“操”。双关语若“干”更自然，可按上下文使用“干”，不得机械全局替换。

## 程序保护

- 保留变量、标签、占位符、转义、说话人标识、翻译块 ID、缩进、编码、BOM、换行符和文件末尾换行。
- 除确认是翻译引入的语法错误外，不修改 label、jump、call、menu、Python、资源路径和分支结构。
- 任何新增/删减变量或格式标签都视为错误，除非英文源字符串本身如此。
- `old`／`new` 形式的菜单选项中，普通陈述句结尾通常不加句号；问号、感叹号及承担明确语气功能的标点保留。
- 中文台词内需要引述内容时，优先使用弯引号 `“……”`，不要使用书名号式直角引号 `「……」`；弯引号是普通文本字符，不影响外层 Ren’Py ASCII 双引号。
- 姓名默认按英文原状保留；手机任务提示等 UI 若把字面 `Anon` 当作玩家占位并绕过自定义姓名，可按界面视角译为“你”。
- `{dom=...}`、`{sub=...}` 的标签名属于格式结构，等号后的文字属于玩家可见内容；保留标签名并汉化显示值，当前统一为 `{dom=强势}`、`{sub=顺从}`。
- PowerShell 通过 Python 管道传递中文前，先把 `$OutputEncoding` 和 `[Console]::OutputEncoding` 设置为 UTF-8；写回时保持原文件 BOM 与换行格式。


## 重复句式的一致性验收

- 本轮验收按用户要求采用全仓分组检查、已确认句式回归和术语审计，不要求逐句重译。
- 同一任务提示与替代分支优先复用句架；改变时间、人物、单复数时，只调整相应信息。首次与再次、现在与将来、肯定与否定必须准确保留。
- 对话按说话人、听话人、关系阶段和上下文比较。目标是文风一致，不是所有相同英文只能有一种中文。
- 扫描结果不能直接批量替换；发现原文注释与相邻剧情不符时，先核实源版本。相似度高不是语义相同的证明。
- 确认的模板写入 `sentence_patterns.json`；专名写入术语表和 `recurring_terms.json`；人物口吻写入角色档案；执行结果写入进度，不另留一次性review报告。
