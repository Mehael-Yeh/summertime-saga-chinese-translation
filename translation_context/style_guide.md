# 中文精修风格指南

更新时间：2026-09-12

## 每文件工作流

1. 完整读取文件；不足时读取前后文件。
2. 先判断地点、剧情阶段、说话人、关系、目的、情绪和分支。
3. 逐条对照英文，识别连续拆句、代词、双关、讽刺、调情及成人含义。
4. 同一英文名词、组合词、称呼或固定表达在短距离内出现 2 次及以上时，先执行跨文件复查并登记，不在当前几行内孤立定译。
5. 只修改目标中文字符串，不移动、合并或拆分 Ren’Py 语句。
6. 完成英文对照、纯中文复读、程序格式三轮检查。
7. 运行 `python tools/validate_translations.py --changed` 和 `python -X utf8 tools/audit_recurring_terms.py --changed --fail-on-mismatch`，再检查 `git diff`。

## 中英文间距（强制）

- 玩家可见译文中，英文姓名、品牌、缩写与相邻中文或中文标点之间不加空格，例如“我找Anon聊过了”“欢迎光临Tony披萨店”“看Pink Channel节目”。
- 英文词组内部的空格保持原样，例如 `Pink Channel`、`Blue Falcon`；不合并英文单词，不改姓名拼写。变量渲染的人名同样直接接中文，例如“我和[saga.cast.debbie]一起”。
- `{i}` 等显示标签不构成可见间隔，标签两侧按实际可见文字处理；变量内部、标签参数、代码、资源路径、英文原文及显式排版间隔不修改。
- 运行 `python -X utf8 tools/audit_mixed_spacing.py` 检查全仓译文，要求零不一致。

## 非地名英文残留

- 月份全称 January 至 December 保留英文：用户确认 June 与角色名共用字符串，翻译成“六月”会影响角色姓名显示。不得用文件位置或静态校验例外假定运行时翻译隔离；未经验证的全局 June→六月 映射禁止加入。原有月份缩写译法本轮不变。

- 按语言而非字母判断：本轮只汉化英文，意大利语、日语、法语等及其罗马字不动；混合语言句不批量替换。
- 普通词句、操作说明与已有中文术语的物品名应翻译；人物姓名、字谜、品牌型号、按键和程序标识先核对用途。具体已修复项、保留理由和待查项见 `english_residuals.md`。
- 不把开发占位符猜译为剧情；当源注释与目标标识符不一致时单列待查。

## 中文表达

- 优先准确、连贯和角色化，不逐词硬译。
- 删除不必要的英文式主语、被动句、从句套叠和“我想知道是否”等机翻结构。
- 不为追求流畅而改变剧情事实、人物关系、行为主体、情绪强度或成人含义。
- 不擅自加梗、加心理活动、加色情细节，也不净化原文。
- 同一角色在同一关系阶段保持稳定语气，但不要把所有角色翻成同一种网络口吻。
- 角色使用引号复述前文台词时，引号内译文必须与前文实际译文完全一致；不得在复述时另换同义词，导致剧情回扣失效。

## 重复称呼、口癖与专名

- 同一表达短距离出现 2 次及以上，是强制复查触发条件；优先判断人物专属称呼、口癖、车辆/物品/地点专名和关系阶段用语。
- 先用 `python -X utf8 tools/audit_recurring_terms.py --query "英文短语"` 搜索全仓英文原文与现有中文，再确定译法。
- 已确认条目写入 `translation_context/recurring_terms.md` 和机器可读的 `translation_context/recurring_terms.json`；人物相关条目同时更新角色档案，固定译法同步更新术语表。
- 跨文件命中不等于可以立即全局替换。未通读的文件只加入复查队列，进入该文件并理解完整场景后再修改。
- 每个已处理文件都要运行重复术语审计；审计脚本只报告，不自动重写。

## 地点名称核对

- 地点定译先核对设定、语气和双关，兼顾信达雅；不合适的 UI 旧译须连同引用同步纠正。地点专名出现一次即核对 `base_box/sets.rpy` 与 `res/meta/sets.rpy` 的 UI 译名，跨对话、任务、物品说明、选项保持一致；固定表及例外见 `terminology.md` 的“地名与 UI 一致性”。
- 不把“人物姓名保留英文”扩展到店名。允许增加类别词，不允许替换核心译名；普通场所词和自然简称按上下文处理。
- 地名专项排查以英中对应和前后文为依据，只修地名相关文本；完成后运行全仓术语审计以及翻译结构检查。

## 连续拆句

- 日记等抽取字符串不一定按显示顺序存放；先核对实际拼接关系，再判断指代与语序。不得把相邻条目误当作连续句，也不得为了中文顺序移动翻译块或格式标签。
- 区分“全仓静态扫描”和“逐句语义审校”；检查记录须注明覆盖数量、已修订范围、待核实项及是否经过游戏内验证。

- 遇到 `...`、`extend`、未完成谓语/宾语或被打断句，必须把连续多行作为一个语义单元理解。英文纯省略号通常译为中文省略号 `……`，不得因编码或管道问题写成 `??`。
- 代码行数和顺序保持不变；只在各字符串内部安排中文停顿和衔接。

## 成人场景

- 与普通剧情同等优先；完整翻译呻吟、喘息、身体反应、性行为和粗俗用语。
- 原文含蓄/挑逗/露骨/粗俗的层级必须对应，不自动升级或降级。
- 主动、被动、命令、抗拒、羞耻、试探和欲望不能混淆。
- 女性角色明确要求与对方发生性行为，且中文动作义采用“操某人／操屄”一类直白结构时，优先把动作字写作“肏”；感叹、惊讶、愤怒或辱骂中的“操”仍保留“操”。双关语若“干”更自然，可按上下文使用“干”，不得机械全局替换。

## 程序保护

- 用户明确要求README不得更改；检查、构建说明归入translation_context对应文件。验证仅运行静态检查、compile和Lint，不进行场景游玩验证。
- 后续完成翻译任务后不默认本地构建`zh_hans.rpa`；只有用户另行要求打包时才构建。此约定不影响必要的静态检查与引擎compile／Lint。
- 清理旧版翻译块须以适配版本引擎实际报告的orphan清单为依据；同时检查句式回归基准是否仍有对应原文，避免保留无效规则。

- 原文注释原则上不改；确认注释已错位时，必须用匹配版本的源档案及翻译块摘要交叉验证后恢复，并记录证据。不得为了让校验通过而将原文注释改成迎合错误译文的内容。
- 可使用 `tools/audit_source_comments.py --source-root <反编译根目录>` 做只读核对。当前工具仅核对剧情文件中能唯一匹配单行语句摘要的块；unverified不是已确认错误，也不应猜测修复。
- 分发RPA须包含编译后的脚本：在隔离的匹配版本游戏副本中编译，再对其game目录使用 `tools/build_rpa.py --require-compiled`。归档字节校验通过不等于游戏已加载翻译，须检查仅安装RPA时引擎是否实际识别zh_hans。

- 保留变量、标签、占位符、转义、说话人标识、翻译块 ID、缩进、编码、BOM、换行符和文件末尾换行。
- 除确认是翻译引入的语法错误外，不修改 label、jump、call、menu、Python、资源路径和分支结构。
- 任何新增/删减变量或格式标签都视为错误，除非英文源字符串本身如此。
- `old`／`new` 形式的菜单选项中，普通陈述句结尾通常不加句号；问号、感叹号及承担明确语气功能的标点保留。
- 中文台词内需要引述内容时，优先使用弯引号 `“……”`，不要使用书名号式直角引号 `「……」`；弯引号是普通文本字符，不影响外层 Ren’Py ASCII 双引号。
- 姓名默认按英文原状保留；手机任务提示等 UI 若把字面 `Anon` 当作玩家占位并绕过自定义姓名，可按界面视角译为“你”。
- `{dom=...}`、`{sub=...}` 的标签名属于格式结构，等号后的文字属于玩家可见内容；保留标签名并汉化显示值，当前统一为 `{dom=强势}`、`{sub=顺从}`。
- PowerShell 通过 Python 管道传递中文前，先把 `$OutputEncoding` 和 `[Console]::OutputEncoding` 设置为 UTF-8；写回时保持原文件 BOM 与换行格式。


## 重复句式的一致性验收

- 本轮验收按用户要求采用全仓分组检查、已确认句式回归和术语审计，不要求逐句重译。
- 同一任务提示与替代分支优先复用句架；改变时间、人物、单复数时，只调整相应信息。首次与再次、现在与将来、肯定与否定必须准确保留。
- 对话按说话人、听话人、关系阶段和上下文比较。目标是文风一致，不是所有相同英文只能有一种中文。
- 扫描结果不能直接批量替换；发现原文注释与相邻剧情不符时，先核实源版本。相似度高不是语义相同的证明。
- 确认的模板写入 `sentence_patterns.json`；专名写入术语表和 `recurring_terms.json`；人物口吻写入角色档案；执行结果写入进度，不另留一次性review报告。

## 翻译块清理与连续对白

删除孤立翻译块前，必须定位当前版本对应的新ID，核对整段实际执行顺序中的前后对白、extend续接及分支；不能仅以Lint无孤立块证明语义完整。翻译文件末尾新增块可能在剧情中间执行，禁止按文件相邻位置推断上下文。迁移时保留原有正确的上下文译法，并复核新动作参数。

## 源码顺序与行号

对白翻译块必须按匹配版本游戏源码中的顺序放置，并在块前标明准确的`# game/路径:行号`。新增ID应插回剧情对应位置，不能集中追加在文件末尾。更新版本时以引擎实际翻译节点的filename和linenumber核对，不用过期注释或反编译文本的物理行数猜测。排序只能移动完整块，不得变更ID、动作参数、变量或译文；字符串表与Python翻译块单独保留。

## 非露骨前后对白专项

本专项只润色非露骨对白，避免新增身体或性行为细节。先区分预约、忙碌拒绝、关系确认、关心、收尾、次晨和任务提示，再调整语气。保留付费条件、拒绝、时间限制和人物态度，不用“更温柔”或“更会调情”代替忠实原意。场景范围按原文label和分支确定；相同短句须查看其回应对象，不能只按词面统一。登记覆盖时明确区分全文对照、局部场景复核与候选扫描。

## 2026-09-12 场景复核与变量补充

- 先追踪源脚本的call／jump和menu入口，再读连续对白。源码顺序正确不代表相邻label运行时连续，尤其不能把前一分支的收尾当成下一分支的前文。
- 短否定句也要复核问答极性：回答“是不是太用力”时NO是“没有”，不是“不要”；真实拒绝仍明确保留。相同英文在接受帮助、婉拒帮助和回答事实时允许不同译法。
- 变量内部禁止中文标点替换。`[when[1]!l]`中的`!l`是格式转换语法，不是句末感叹号。只检查内部`[1]`不足以发现损坏；validate_translations现补查嵌套索引后的转换后缀。
- 本次继续遵守：不改README，不构建RPA，不进行场景游玩验证。只读静态审计及隔离环境Lint的通过不能替代游戏内视觉和日记拼接验证。

## 分段对白的连贯性审校

- 以匹配版本引擎的对白节点及call／return、jump、if、menu关系定位前后文；物理相邻行只用于定位，不能证明执行连续。静态遍历枚举的是可能路径，不能证明所有条件组合在游戏中可达。
- 先把一个意思的全部分段连读，再决定每段译文。英语后置的too、of my life、关系从句和宾语可按中文语序分配到同一连续句组中；保留翻译块、ID、源行号、动作、变量、标签和停顿位置，不逐词硬对齐。
- extend是在同一文本上追加内容。检查实际拼接结果，不在前段末尾和续接开头重复添加省略号。计时专用或空extend保留；不得为了“读着顺”删掉节点。
- 共用后半句须检查所有入口。遇到“不光……但……”之类分支关联词冲突，可改用各分支都成立的自然陈述；保留优惠、付款、时间及人物态度等事实，不擅改分支逻辑。
- 区分语病与角色有意重说。被打断后重新起句、犹豫、口吃、插入感叹或动作引起的重复应保留；不能把源文明确的重启一律当赘词删掉。跨过亲吻、喘息或沉默才能接完整的句子，也须回看这些中间节点。
- sentence_patterns.json支持可选id，约束具体翻译块；无id的旧规则仍检查该文件全部同源句。分段中的“Oh.”等不能据局部译法全局替换。规则只能发现译文偏离，不能自动证明剧情连贯。
- validate_translations的原译配对允许源注释与对白之间出现nvl clear，确保教程清屏后的文本也被检查；不会跳过jump等控制流语句寻找目标。

## 既有露骨对白的忠实性与语义校对

本轮按用户要求，将忠实翻译、语义纠错和连贯性调整扩展到已有露骨对白。以源文为限，不增加动作、部位、体液、羞辱或力度，不扩写场景；既有非露骨专项记录仍只代表当时的范围。

- 先核对说话人、受话人、动作状态和分支，再判定词义。Give it to me在过程中的催促与射精前的请求不同；take it all的接收者不能反译为索取者。
- cum按说话人与上下文区分高潮、射精及预告／正在发生／事后回顾。只有源文或对应动作明确支持时才具体译为喷射；不能把每次高潮都加写成潮吹，也不能把高潮误作填满。
- 保留力度差别：harder、pound、murder等不能全部归为同一强度；一般催促不额外加“再狠一点”，部位名也不自动增加“骚”等评价。粗俗原文不一律净化，温和原文不主动粗俗化。
- 位置与条件不可省略：on your back是仰面躺下；still hitting the right spot询问是否仍顶着正确位置。inside／outside、pull out、stop／don't stop的区别必须明确保留。
- 分段可以调整中文词序，但须整组连读：例如“你应该……／……射在……／……我里面。”不能把位置同时写进两段。纯喘息Haaaah不按Hahaha译成笑声；真正笑声和口吃仍保留。
- 不把疼痛、不适、拒绝、停止请求改成鼓励。某角色在其他分支接受过，不代表本分支同意；拒绝内射与要求不中断也不能相互替代。

用户确认：忠实性同时包括语用强度与人物口吻。不能仅因源文没有逐字对应“烂”或“骚”，就认定角色化的夸张表达是增译。Tina的Pound that pussy保留用户认可的原译；纠错应优先处理事实、施受关系与衔接错误，不以中性化替代忠实。

## 全库筛查后的语境复核

- 自动筛查负责定位，不能代替整组阅读。日记字符串须按匹配版本的实际页序连读，不能按bytecode_strings.rpy词条顺序推断上下文。保留颜色、字号、旁注和图形标签；去标签连读只核查语义，不代表画面布局已验证。
- 拆句可在连续片段之间重新分配中文词序，但须保留全部含义。“他一直在／最近钱很多”应整体理解为最近手头宽裕；“这事能／工作”的work是行得通。不能删除短句或把补回的段落移到文件尾。
- 自然化不能改变关系程度：身体反应不擅改成动心，当下体验不扩大为恋爱表白；两个并列问句不能改成二选一。
- Jenny日记保留自负、挖苦和口是心非；MEATHEAD、PUSSY按当页对象辨义，不把骂人怂译成身体部位。不用中性化代替校对，仍保留原有粗口与夸张。

## 姓名后称谓与含混发音

Princess Jenny按中文习惯译为“[saga.cast.jenny]公主”，包括斜体称谓；强调标签继续包住“公主”，不能包错姓名。单独出现的princess不补姓名。其他称谓先判断语境，不能机械改成前置。含混拼写先还原语义，再用自然停顿传达说话状态，不以大量错别字或无依据的口吃降低可读性；得意、调侃和抱怨仍须保留。

## 口头填充语与整句自然度

Like、apparently、I dunno等须按句中作用处理：口头起句的Like不是举例，不硬译“比如”；听来的消息用“听说”，不把apparently一律写成“显然”；I dunno承接反常行为时用“不知道怎么回事”，不留下“但不知道”的半截中文。称赞主意的genius可译“这主意绝了”，不要把主意误写成一个天才人物。

## 短回应的语用区别

You better believe it作为肯定回答可用“那还用说”，不是威胁式“你最好信”。If you say so要区分勉强接受（“好吧，你都这么说了”）与不以为然（“随你怎么说”），不能全局归为同一句，更不能留下条件从句。I mean在修正说法或承接抱怨时按功能处理；pretty sure保留把握程度，不擅改成完全确定。

## 连续审读与反查改动

- 先区分寒暄、菜单选项、命令、讽刺和实际询问。Not much回应近况时译“没什么事”，不是“不太多”；门上的Locked译“门锁着”，不是功能“已锁定”。
