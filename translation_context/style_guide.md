# 中文精修风格指南

更新时间：2026-09-13

用途与维护方式见[index.md](index.md)。

## 每文件工作流

1. 完整读取文件；不足时读取前后文件。
2. 先判断地点、剧情阶段、说话人、关系、目的、情绪和分支。
3. 逐条对照英文，识别连续拆句、代词、双关、讽刺、调情及成人含义。
4. 同一英文名词、组合词、称呼或固定表达在短距离内出现 2 次及以上时，先执行跨文件复查并登记，不在当前几行内孤立定译。
5. 只修改目标中文字符串，不移动、合并或拆分 Ren’Py 语句。
6. 完成英文对照、纯中文复读、程序格式三轮检查。
7. 运行 `python tools/validate_translations.py --changed` 和 `python -X utf8 tools/audit_recurring_terms.py --changed --fail-on-mismatch`，再检查 `git diff`。

验证边界：不改 README，不构建 `zh_hans.rpa`（除非用户另行要求），不进行场景游玩验证。只读静态审计、隔离环境 Lint 和结构校验通过，不能代替游戏内视觉、日记拼接和逐场景验证。

## 场景连读方法（中文优先）

- 按实际场景和分支先连续阅读中文，检查口头语直译、指代、角色语气、重复句式和分段衔接；遇到疑点再回查原文、前后对白及必要的动作和分支条件，不靠孤立句子猜意思。使用 `tools/read_scene_chinese.py` 辅助中文连读，未定位译文必须回查。
- 台账用 `chinese_scene_read` 记录中文连读，`source_checks` 单独记录回查原文的范围与原因；不得把中文连读计作全条双语核对。原剧情有意保留的矛盾或角色错误判断，不按译者常识改写。正式谈话中，同一角色对同一对象的您／你应保持一致，除非情境显示态度变化。
- 先追踪源脚本的 call／jump 和 menu 入口，再读连续对白。源码顺序正确不代表相邻 label 运行时连续，尤其不能把前一分支的收尾当成下一分支的前文。
- 对白翻译块必须按匹配版本游戏源码中的顺序放置，并在块前标明准确的 `# game/路径:行号`。新增 ID 应插回剧情对应位置，不能集中追加在文件末尾；更新版本时以引擎实际翻译节点的 filename 和 linenumber 核对，不用过期注释或反编译文本的物理行数猜测。排序只能移动完整块，不得变更 ID、动作参数、变量或译文；字符串表与 Python 翻译块单独保留。
- 以匹配版本引擎的对白节点及 call／return、jump、if、menu 关系定位前后文；物理相邻行只用于定位，不能证明执行连续。静态遍历枚举的是可能路径，不能证明所有条件组合在游戏中可达。
- 自动筛查负责定位，不能代替整组阅读。日记字符串须按匹配版本的实际页序连读，不能按 `bytecode_strings.rpy` 词条顺序推断上下文。
- 中文阅读工具不能仅凭旧行号匹配共享菜单：old／new 菜单按原文字符串解析，普通对白也须核对当前源行字符串，避免旧菜单条目落到 return 或 with 代码行。无法定位时明确标出待回查，不猜译文；显示工具不授予人工覆盖。

### 分段对白的连贯性审校

- 先把一个意思的全部分段连读，再决定每段译文。英语后置的 too、of my life、关系从句和宾语可按中文语序分配到同一连续句组中；保留翻译块、ID、源行号、动作、变量、标签和停顿位置，不逐词硬对齐。
- extend 是在同一文本上追加内容。检查实际拼接结果，不在前段末尾和续接开头重复添加省略号。计时专用或空 extend 保留；不得为了“读着顺”删掉节点。
- 共用后半句须检查所有入口。遇到“不光……但……”之类分支关联词冲突，可改用各分支都成立的自然陈述；保留优惠、付款、时间及人物态度等事实，不擅改分支逻辑。
- 区分语病与角色有意重说。被打断后重新起句、犹豫、口吃、插入感叹或动作引起的重复应保留；不能把源文明确的重启一律当赘词删掉。跨过亲吻、喘息或沉默才能接完整的句子，也须回看这些中间节点。
- 遇到 `...`、`extend`、未完成谓语／宾语或被打断句，必须把连续多行作为一个语义单元理解。英文纯省略号通常译为中文省略号 `……`，不得因编码或管道问题写成 `??`。
- 分屏台词必须合起来检查主语和宾语。例如 `ano06` 的 We want／Our money／Back 采用“我们要你……／把我们的钱……／还回来。”，保留逐屏施压的节奏，不能连成讨债人自己还钱。
- 复述问句要承接前句实际使用的中文词语：前句把 hotel debacle 译为“订酒店折腾”，后句 Debacle? 应追问“怎么折腾”，而非突然换回“闹剧”。`yoo` 的 Conquer? 承接“拿下车行”，译“拿下车行？”。
- 首次／再次等省略指代必须接读前句和入口分支。first time 不自行扩成“第一次跟别的男人上床”；原文未限定的经历不补写，避免与此前剧情冲突。
- 代词指代不清时可补明已列出的两个人，但不能把未列出的第三人提前算入。翻译某人身份未知或未见过面时，避免把“不知道对方是谁”和“没见过对方”拼成“对方是谁都没见过”。
- 复述上句关键词的短反问要接住上句实际中文用词；明确 and I quote 的回述与先前同句译文保持一致。

### 连续审读与反查改动

- 先区分寒暄、菜单选项、命令、讽刺和实际询问。Not much 回应近况时译“没什么事”，不是“不太多”；门上的 Locked 译“门锁着”，不是功能“已锁定”。
- 反查润色是否额外解释了上一句。短回应只需表达理解或认可，不能为了自然重述整个前句。命令中的 Now 与告别中的 soon 按语用处理，不凭它们新增立即见面或固定时间承诺。
- 未完句应保留未完成的内容。例如“这一切都——／没了？”不在前句预先补上“没了”；“你夹得我……／有点……／感叹”不提前写完程度，也不补出被打断的部位。
- 标签的语义归属也要核对，不能只看数量。强调 that 时保留强调位置；Coming soon／later 的删除线属于被否定的“很快”。格式校验不代替这类人工判断。
- 同源喘息在不同结果分支中仍是喘息，HNNGGG 不能因拼写重复误作哈哈笑声。拉长音与重复喊叫要区分，不把原文一次拉长感叹机械复制成多个词。

### 按物品流转和说话时点核对语义

- get something back to somebody 先核对物品来处；新取得的材料是“带回去交给”，不凭 back 译成“归还”。be right back with 物品表示先去取、随后带回来，不能写成“回来拿”。
- 比喻性 bill 先看是否真的收钱；替别人承受告解等后果不写成自掏腰包，可用“替我付出代价”保留玩笑。
- 对未来事件感到紧张用“一想到下午的事就紧张”，不写成当前已经是下午。明天与星期变量分支使用一致句架，保留各自时间条件。
- 嘲讽性的 Yeah, right 和 Ga-doy 应读成不信与“这还用问”，不机械当成肯定或惊叹；先连读提问、反应和后续证据。
- 按物品流转、说话时点和动作对象核对：小黑裙备注的 shouldn’t 指不让主角购买；雕像躯干是主角拿海狸玩偶向 Clyde 换得。

### 规矩、后续指令与数量语义

- address somebody 在发言权限的语境里是“对某人说话”，与称呼规则分开核对。后文破例允许说话，应与前文禁止直接发言对应。
- 检查一条源文内的多项指令是否全部保留；“回家睡觉，我去装裱送赛”不能漏掉前半句，否则后面的晚安失去铺垫。
- a lot 区分数量、程度与次数，不凭中文顺口添成“几次”；强调下一段的 Every single time 不预先搬入前一段。
- 同一场景中的规矩一、二、三使用一致说法。未完句、停顿和被打断的抱怨仍按原顺序保留。地址、地址编号与门锁提示按场景实体处理，不机械替换。

### 展示对象、重复安慰与未完解释

- I would rather not 省略了什么，要承接上一个请求。让角色展示自己的画时，回答是不愿给别人看，不是自己不愿看。
- 同一人物在一个场景重复安慰或提醒时，应保留能让玩家认出的中文句架，例如两次“艺术没有好坏之分”。
- 被打断的否认保留原主语：they are not 不能变成“我不是”。不在 Awes- 或 I coul- 里预先补完整句；各次中断仍留在原翻译块中。
- Chad 的 yo、dawg 等按口吻处理，少用每句末尾机械追加“哟”；不因此削弱其粗口。

## 中英文间距（强制）

- 玩家可见译文中，英文姓名、品牌、缩写与相邻中文或中文标点之间不加空格，例如“我找Anon聊过了”“欢迎光临Tony披萨店”“看Pink Channel节目”。
- 英文词组内部的空格保持原样，例如 `Pink Channel`、`Blue Falcon`；不合并英文单词，不改姓名拼写。变量渲染的人名同样直接接中文，例如“我和[saga.cast.debbie]一起”。
- `{i}` 等显示标签不构成可见间隔，标签两侧按实际可见文字处理；变量内部、标签参数、代码、资源路径、英文原文及显式排版间隔不修改。
- 运行 `python -X utf8 tools/audit_mixed_spacing.py` 检查全仓译文，要求零不一致。

## 非地名英文残留

- 月份全称 January 至 December 保留英文：用户确认 June 与角色名共用字符串，翻译成“六月”会影响角色姓名显示。不得用文件位置或静态校验例外假定运行时翻译隔离；未经验证的全局 June→六月 映射禁止加入。原有月份缩写译法不变。
- 按语言而非字母判断：只汉化英文，意大利语、日语、法语等及其罗马字不动；混合语言句不批量替换。
- 普通词句、操作说明与已有中文术语的物品名应翻译；人物姓名、字谜、品牌型号、按键和程序标识先核对用途。
- 检查范围不能只统计英文残留：英文已替换成中文也可能漏解。已修复项、保留理由与例外见 [english_residuals.md](english_residuals.md)。

## 中文表达

- 优先准确、连贯和角色化，不逐词硬译。
- 删除不必要的英文式主语、被动句、从句套叠和“我想知道是否”等机翻结构。
- 不为追求流畅而改变剧情事实、人物关系、行为主体、情绪强度或成人含义。
- 不擅自加梗、加心理活动、加色情细节，也不净化原文。
- 同一角色在同一关系阶段保持稳定语气，但不要把所有角色翻成同一种网络口吻。
- 角色使用引号复述前文台词时，引号内译文必须与前文实际译文完全一致；不得在复述时另换同义词，导致剧情回扣失效。
- Like、apparently、I dunno 等须按句中作用处理：口头起句的 Like 不是举例，不硬译“比如”；听来的消息用“听说”，不把 apparently 一律写成“显然”；I dunno 承接反常行为时用“不知道怎么回事”，不留下“但不知道”的半截中文。称赞主意的 genius 可译“这主意绝了”，不要把主意误写成一个天才人物。
- You better believe it 作为肯定回答可用“那还用说”，不是威胁式“你最好信”。If you say so 要区分勉强接受（“好吧，你都这么说了”）与不以为然（“随你怎么说”），不能全局归为同一句，更不能留下条件从句。I mean 在修正说法或承接抱怨时按功能处理；pretty sure 保留把握程度，不擅改成完全确定。
- 英语省略回答须承接中文前句的具体意思：夸宝宝漂亮后的 Yeah, he/she is 译“是啊，真漂亮”，复数保留“都”；Not one bit 承接不喜欢，写“一点儿也不喜欢”；未确定是否来店是计划未定，不写容易误作能力或信心不足的“没把握”。
- Aww 承接请求被拒绝时表达失望，不用表示意外出事的“啊哦”。Really? 须区分询问真假和对行为的责怪。
- 男婴、女婴、双胞胎替代分支沿用相同句式，同时保留他／她／他们及相应单复数信息。照看孩子用“照看”，接过怀中婴儿用“抱”，不能机械译成“带”。

## 姓名后称谓与含混发音

Princess Jenny 按中文习惯译为“[saga.cast.jenny]公主”，包括斜体称谓；强调标签继续包住“公主”，不能包错姓名。单独出现的 princess 不补姓名。其他称谓先判断语境，不能机械改成前置。含混拼写先还原语义，再用自然停顿传达说话状态，不以大量错别字或无依据的口吃降低可读性；得意、调侃和抱怨仍须保留。

## 重复称呼、口癖与专名

- 同一表达短距离出现 2 次及以上，是强制复查触发条件；优先判断人物专属称呼、口癖、车辆／物品／地点专名和关系阶段用语。
- 先用 `python -X utf8 tools/audit_recurring_terms.py --query "英文短语"` 搜索全仓英文原文与现有中文，再确定译法。
- 已确认条目写入 `recurring_terms.md` 和 `recurring_terms.json`；人物相关条目同时更新角色档案，固定译法同步更新术语表。
- 跨文件命中不等于可以立即全局替换。未通读的文件只加入复查队列，进入该文件并理解完整场景后再修改。
- 每个已处理文件都要运行重复术语审计；审计脚本只报告，不自动重写。具体条目、句式基准与语境边界见 [recurring_terms.md](recurring_terms.md)。

## 地点名称核对

- 地点定译先核对设定、语气和双关，兼顾信达雅；不合适的 UI 旧译须连同引用同步纠正。地点专名出现一次即核对 `base_box/sets.rpy` 与 `res/meta/sets.rpy` 的 UI 译名，跨对话、任务、物品说明、选项保持一致；固定表及例外见 [terminology.md](terminology.md) 的“地名与 UI 一致性”。
- 不把“人物姓名保留英文”扩展到店名。允许增加类别词，不允许替换核心译名；普通场所词和自然简称按上下文处理。
- 地名专项排查以英中对应和前后文为依据，只修地名相关文本；完成后运行全仓术语审计以及翻译结构检查。

## 成人场景

- 与普通剧情同等优先；完整翻译呻吟、喘息、身体反应、性行为和粗俗用语。
- 原文含蓄／挑逗／露骨／粗俗的层级必须对应，不自动升级或降级。
- 主动、被动、命令、抗拒、羞耻、试探和欲望不能混淆。
- 女性角色明确要求与对方发生性行为，且中文动作义采用“操某人／操屄”一类直白结构时，优先把动作字写作“肏”；感叹、惊讶、愤怒或辱骂中的“操”仍保留“操”。双关语若“干”更自然，可按上下文使用“干”，不得机械全局替换。

### 既有露骨对白的忠实性与语义校对

以源文为限，不增加动作、部位、体液、羞辱或力度，不扩写场景。

- 先核对说话人、受话人、动作状态和分支，再判定词义。Give it to me 在过程中的催促与射精前的请求不同；take it all 的接收者不能反译为索取者。
- cum 按说话人与上下文区分高潮、射精及预告／正在发生／事后回顾。只有源文或对应动作明确支持时才具体译为喷射；不能把每次高潮都加写成潮吹，也不能把高潮误作填满。
- 保留力度差别：harder、pound、murder 等不能全部归为同一强度；一般催促不额外加“再狠一点”，部位名也不自动增加“骚”等评价。粗俗原文不一律净化，温和原文不主动粗俗化。
- 位置与条件不可省略：on your back 是仰面躺下；still hitting the right spot 询问是否仍顶着正确位置。inside／outside、pull out、stop／don't stop 的区别必须明确保留。
- 分段可以调整中文词序，但须整组连读：例如“你应该……／……射在……／……我里面。”不能把位置同时写进两段。纯喘息 Haaaah 不按 Hahaha 译成笑声；真正笑声和口吃仍保留。
- 不把疼痛、不适、拒绝、停止请求改成鼓励。某角色在其他分支接受过，不代表本分支同意；拒绝内射与要求不中断也不能相互替代。
- 忠实性同时包括语用强度与人物口吻。不能仅因源文没有逐字对应“烂”或“骚”，就认定角色化的夸张表达是增译。用户认可的粗野催促原译保留；纠错应优先处理事实、施受关系与衔接错误，不以中性化替代忠实。

## 重复句式的一致性验收

- 验收采用全仓分组检查、已确认句式回归和术语审计，不要求逐句重译。
- 同一任务提示与替代分支优先复用句架；改变时间、人物、单复数时，只调整相应信息。首次与再次、现在与将来、肯定与否定必须准确保留。
- 对话按说话人、听话人、关系阶段和上下文比较。目标是文风一致，不是所有相同英文只能有一种中文。
- 同一人物的任务邀约、提醒及替代分支保持基本语气一致；人物之间的称谓、礼貌程度及关系变化不能因原句相同而抹平。
- 扫描结果不能直接批量替换；发现原文注释与相邻剧情不符时，先核实源版本。相似度高不是语义相同的证明。
- 确认的模板写入 `sentence_patterns.json`；专名写入术语表和 `recurring_terms.json`；人物口吻写入角色档案；执行结果写入 `progress.md`，不另留一次性报告。

## 具体语境示例与易错译法

### 任务、界面与系统提示

- 图书馆结算入口 check out 指办理借阅，不能译作“看看”。共享购买菜单用“花金额购买物品”，Borrow 用“借阅”，动态商品名保留。
- 店员询问需要帮助或介绍服务后，I am fine 可表示婉拒，应结合后句译为“不用了”，不机械译作“我很好”。
- 办公室语境 hold my calls 表示暂不把来电转给本人，并非要求前台停止接听电话；角色替换分支应同步纠正。
- 电脑和主播资料中的 cam 在直播语境译为“直播”，勿写“摄像头服务”。商城 75% OFF 表示降价 75%，即二五折，不是七五折。邮件 TRASH 为“已删除”，与 SPAM“垃圾邮件”区分；Pink 电视订阅使用“Pink频道”，与“粉色诱惑”商店区分。
- Cedric 健身菜单 Can you spot me 为请人保护训练，不能译为借钱；与选项后对白统一为“你能帮我护着点儿吗”。
- Bridget 训练问答先问在哪儿再问练什么；Hana 的 owner 为“店老板”，I did 承接姓名确认，不是做过某事。
- 校园 detention 应按语境译“课后留堂”，不能混为“留校察看”。借阅任务中 overdue 指“逾期未还”，不是书本过期；log 按上下文译“借阅记录”。
- 任务菜单按对话内容译主题；Eve 的 Tutor 指向辅导课问询，采用“课后辅导”，不按孤立名词译“导师”。
- watch 在被禁止操作实验后的指令中指“旁观”，不是看管同学；do anything right 指“把事情做对”，不是做好事；发现道具时 Here is 译“在这儿”，不套成递物用语“给你”。
- 图书馆与商店的角色接待、购买与借阅入口按同一术语表处理；共享菜单的短句不因同形而覆盖独立对白。

### 短答与问答极性

- 短否定句也要复核问答极性：回答“是不是太用力”时 NO 是“没有”，不是“不要”；真实拒绝仍明确保留。相同英文在接受帮助、婉拒帮助和回答事实时允许不同译法。
- Definitely 等肯定答语先核对前问：`deb08` 试衣菜单是在肯定裙子好看，应为“当然！”，不能误作“当然愿意！”。
- Yeah right 依语境可为反讽“才怪”；Nope 等否定短答须保留前问语义（are you sure → “不确定”），不能机械译成拒绝意味的“才不”。
- Really? 须区分询问真假和对行为的责怪；`tin02_liu.tina` 承接主角再次公开提起私事，采用“你还说这个”，不把 Tina 的责怪写成期待的追问。
- 共用菜单 Not really. 在 `deb14` 的是否想过、`jen05` 的照片评价和 Viv 两个地点的问事语境中采用“倒也没有”，避免全局共享短句写成只有一种提问能用的“没怎么想过”。
- 短答 I am 须回扣前问（are you sure → “我确定”）；Would you like that 须回指上一句提议，不凭空引入称呼。
- Tell me something I do not know 在接受夸奖的自得回应中可译“那还用你说”，不机械当作索取信息。

### 道具、身体与动作指代

- 同一道具在普通对白中称“润肤乳”，商品标签明确写 cream 时保留“润肤霜”。回忆按摩时明确主角给 Debbie 按摩，避免“和她按摩”模糊施受关系。
- Thick and delicious 在试衣评价身材的语境中译“丰满又诱人”，不把 thick 误译为浓度；菜单与后续曲线赞美连读。
- down here 按动作明确为腿部皮肤，避免中文“下面”产生位置误解；extra special 的调侃保留前后呼应。
- Dreams 须区分梦境与人生梦想；Debbie 任务菜单讨论怪梦，统一“梦境”。内心独白的重复否定可以自然化，但保留逐渐坚定的语气。
- This will work 在挑选电视节目时按接受该节目译“先看这个吧”。旁白的复杂英文句法可拆顺，但保留故作玄虚与自嘲意味，不凭空添加“假装”等动机。
- You know 作为解释后的确认语可译“你懂我的意思吧”；I have got it 结合起身接手动作译“我来就好”；评论影片的 concept 指“剧情设定”。
- go to bed 与 fall asleep 须区分“上床休息”与“睡着”，尤其紧接失眠对白时；相关问答一起调整，避免前句说睡了后句说始终睡不着。
- I have got it 回应是否需要帮忙时，结合尚未开始工作的上下文译“我能搞定”，不提前宣告完成；电话 the other end 按来电／接听关系表达，避免把来电者说成接电话的人。
- Got it 须按动作时点区分“知道了”和“取下来了”；Ursula 以失业相威胁后的 understanding 是“听明白了吗”，不是平等协商达成共识。
- no escape／Not for me 这类连续片段须合读，区分无法摆脱与主动不想离开，不把强调对象误作重复意愿。
- 道具说明必须核对动作对象与所有权，物品描述中的 ticket 习语可以表达为线索，避免把具体物件写成抽象办法。

## 翻译块清理与连续对白

删除孤立翻译块前，必须定位当前版本对应的新 ID，核对整段实际执行顺序中的前后对白、extend 续接及分支；不能仅以 Lint 无孤立块证明语义完整。翻译文件末尾新增块可能在剧情中间执行，禁止按文件相邻位置推断上下文。迁移时保留原有正确的上下文译法，并复核新动作参数。清理旧版翻译块须以适配版本引擎实际报告的 orphan 清单为依据，同时检查句式回归基准是否仍有对应原文。

## 提取文本维护规则

1. 先查 `extracted_routes.json` 的源码模块映射，再确定 `tl/zh_hans/extracted/` 归属。不得重建 `bytecode_strings.rpy`，也不以文件长度、关键词或人物名直接分类。
2. 精确 old 键是 Ren’Py 全语言共享的查找键；同一键即使有多个调用者，也只维护一个归属。新增前搜索整个 `tl/zh_hans`，复用已有条目，不在多个分类重复生成。
3. diary 按事件内页序合读；messages 按发送事件核对；gallery 保留首次／重复、阶段与触发条件区别。新增条目优先靠近同源条目，保留可核实的来源注释，未知行号不得编造。
4. diagnostics 包含提取器误收的内部字段，不能把它们当玩家对白任意改名或删除；未定位的旧键明确保留待核。compatibility 只承担名字兼容用途。
5. calendar 中的相对日期和月相与角色 June 无关；不得据此批量翻译角色姓名或月份名称。
6. 迁移或新增后同步 `sentence_patterns.json` 的 file 与 `manual_review.json` 的文件哈希、条目行号、分页行号。旧笔记自由文本里的旧行号属于历史记录，迁移不增加人工审读覆盖，也不关闭外部事件待办。
7. 日记阅读工具默认读 `extracted/jenny_diary.rpy`；使用 `tools/read_diary_pages.py` 生成新快照后审读，不沿用聚合文件缓存。
8. 提取翻译保留 Ren’Py 所需的 `.rpy` 扩展名，按源模块词干命名：gallery→lewd、messages→mesg、diary→jenny_diary，其余多源文件采用模块名组合，完整对应表见 `extracted_routes.json`。文件内容及条目顺序不因改名改变；工具默认路径、审校记录、句式回归及依赖路径同步迁移。
9. 排序规则按源码出现顺序：日记按事件注册顺序、事件内页序和行序排列，并附 event／page／row 定位；短信按发送事件注册顺序；其余文件先按来源模块分组，再按模块内首次出现位置排序。同一 old 键只保留一份，以首次出现位置为准；未定位旧键放在 diagnostics 末尾并保留待核标记。不同事件可分支或动态解锁，这里是可核实的源码顺序，不是唯一固定的游玩时间线。
10. 拆分后的运行时消费者：`sms_fix.rpy` 使用 `renpy.list_files` 发现 `tl/zh_hans/extracted` 下全部 rpy，再用 `renpy.loader.load` 读取，避免固定依赖聚合文件；新增分类无需修改加载清单。执行 `tools/check_sms_mapping.py` 检查短信映射、前置回调及新增文件发现，它使用隔离的 Ren’Py 替身，不等同于游戏游玩验证。

仅文件组织发生变化时，不改 old／new 内容、变量、标签、中文措辞或非英语文本。

## 日记可读性验收

jenny_diary.rpy 共 294 条，按页段顺序连同正文、旁注、跨行残句与指代复核，`readability_review` 状态为 `passed`，范围限定为 `text_level_only`。验收要求：

- 按页连续读正文，分别读旁注并核对锚点，再检查跨行残句与指代；局部改字不自动使整页通过。

- 用户明确要求 README 不得更改；检查、构建说明归入 `translation_context` 对应文件。验证仅运行静态检查、compile 和 Lint，不进行场景游玩验证。
- 后续完成翻译任务后不默认本地构建 `zh_hans.rpa`；只有用户另行要求打包时才构建。此约定不影响必要的静态检查与引擎 compile／Lint。
- 原文注释原则上不改；确认注释已错位时，必须用匹配版本的源档案及翻译块摘要交叉验证后恢复，并记录证据。不得为了让校验通过而将原文注释改成迎合错误译文的内容。
- 可使用 `tools/audit_source_comments.py --source-root <反编译根目录>` 做只读核对。当前工具仅核对剧情文件中能唯一匹配单行语句摘要的块；unverified 不是已确认错误，也不应猜测修复。
- 分发 RPA 须包含编译后的脚本：在隔离的匹配版本游戏副本中编译，再对其 game 目录使用 `tools/build_rpa.py --require-compiled`。归档字节校验通过不等于游戏已加载翻译，须检查仅安装 RPA 时引擎是否实际识别 zh_hans。
- 保留变量、标签、占位符、转义、说话人标识、翻译块 ID、缩进、编码、BOM、换行符和文件末尾换行。
- 除确认是翻译引入的语法错误外，不修改 label、jump、call、menu、Python、资源路径和分支结构。
- 任何新增／删减变量或格式标签都视为错误，除非英文源字符串本身如此。
- 变量内部禁止中文标点替换。`[when[1]!l]` 中的 `!l` 是格式转换语法，不是句末感叹号；只检查内部 `[1]` 不足以发现损坏，`validate_translations` 现补查嵌套索引后的转换后缀。
- `old`／`new` 形式的菜单选项中，普通陈述句结尾通常不加句号；问号、感叹号及承担明确语气功能的标点保留。
- 中文台词内需要引述内容时，优先使用弯引号 `“……”`，不要使用书名号式直角引号 `「……」`；弯引号是普通文本字符，不影响外层 Ren’Py ASCII 双引号。
- 姓名默认按英文原状保留；手机任务提示等 UI 若把字面 `Anon` 当作玩家占位并绕过自定义姓名，可按界面视角译为“你”。
- `{dom=...}`、`{sub=...}` 的标签名属于格式结构，等号后的文字属于玩家可见内容；保留标签名并汉化显示值，当前统一为 `{dom=强势}`、`{sub=顺从}`。
- PowerShell 通过 Python 管道传递中文前，先把 `$OutputEncoding` 和 `[Console]::OutputEncoding` 设置为 UTF-8；写回时保持原文件 BOM 与换行格式。

## 游戏内输入代码兼容

谜题密码与可输入代码不能只改显示译文。翻译线索词语时，同时保留原文输入并为中文添加设备级明确别名；随机字母、数字代码默认不翻译。校验值、输入归一化、兼容脚本及新增规则见 [input_codes.md](input_codes.md)。当前 Jenny 电脑兼容“坏怪物”和攻略写法“BAD MONSTER”，电视订阅码与密码保留原值。

## 一次性清单的归档方式

固定清单类任务（原始问题清单、待核队列、批次核对表）在完成后把结论并入 `progress.md`、`extracted_language_review.json` 或对应规范文件，一次性清单文件不再保留。清单完成表示该批校对流程走完，不等于全库译文质量认证；露骨段落只做语义准确性与通顺度校对，不扩展原文没有的描写。
